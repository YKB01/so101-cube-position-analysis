# 截断对照测试 C_trunc vs C（预注册）

本文件在测试开始前写定，测试期间不修改。

## 目的
复测（`protocol/right_side_retest.md`）中，模型 R（专家 50 + 人类纠正 20）在 P1、P2 上明显差于模型 C（专家 50 + 新增专家 20）。
本测试检验假设 **H1：纠正数据缺少从起始姿态到抓取的完整接近过程**，是否能解释这个差距。

- H1：纠正数据每条都从任务中途开始（第一帧离起始姿态约 217 个关节单位），只包含约 3.7 秒的抓取前动作，
  专家示教约 7.2 秒（`retest_analysis/data_comparison.md`）。
- H2（纠正动作更慢、更不连贯）在数据比较中未得到支持。
- H3：纠正数据"从偏离状态出发的精细修正"这类内容本身的差异。**本测试不复现 H3**，只检验 H1。

## 已有结果（复测，2026-11-14 13:45–15:11，R 与 C 交替测试）
P1 + P2：模型 R 7/16，模型 C 15/16（P1：R 3/8、C 7/8；P2：R 4/8、C 8/8）。

## 被比较的模型
- **C_trunc**：50 条原专家 + 20 条"路程对齐截断"的新增专家。
- **C**：50 条原专家 + 20 条完整的新增专家（复测中的模型 C，同一个 checkpoint）。
- 训练：两者都从 `act_red_cube_50_100000` 微调，5000 步，批大小 8，lr 5e-6，种子 42，无上采样、无采样权重。
  C_trunc 与 C 的 `train_config.json` 除数据集外完全相同。步数不按帧数换算。
- 测试时模型以 A/B 编码，对应关系封存在 `protocol/trunc_model_key.json`，其 SHA-256 在 `protocol/trunc_model_key.sha256`；
  key 文件在测试全部结束后才提交。操作者在测试期间不应查看对应关系。

## C_trunc 数据集的构造
- 配对：20 条新增专家与 20 条纠正数据按方块位置最优配对（欧氏距离，平均 7.8 px，最大 18.6 px）。
- **截断规则（路程对齐）**：对每条新增专家，保留抓取前手臂路程（5 个手臂关节，`observation.state`）与配对纠正数据
  "从第一帧到第一次抓取"的路程相同的部分（截断点取路程最接近的那一帧），加上抓取之后的全部。
- **规则的修改过程**：原计划的规则是"保留从手臂离起始姿态的距离第一次 ≥ 配对纠正数据第一帧距离的那一帧开始的部分"。
  该规则不可行：20 条里只有 10 条能达到阈值（纠正数据的接管姿态不在专家轨迹上），能达到的 10 条里只有 6 条抓取仍在保留部分，
  截断后总共 3,481 帧（纠正数据 9,413 帧）。因此改为路程对齐。**这一修改发生在生成数据集和任何测试之前。**
- 结果：总帧数 8,706（纠正数据 9,413，−7.5%）；每条路程与配对纠正数据相差最大 1.9 个关节单位（中位数 58.4 对 57.8）；
  抓取前时间中位数 1.6 秒（纠正数据 3.7 秒）；第一帧离起始姿态的距离中位数 159（纠正数据 217）。
- 合并数据集（70 条，38,607 帧）已与原始数据逐帧核对：状态、动作、时间戳和每一帧图像完全一致
  （`trunc_control/verification.txt`）。
- 构造方法：只在元数据层截断，不重新编码视频；脚本 `scripts/pair_and_truncate.py`、`build_trunc_dataset.py`、`verify_trunc_dataset.py`。

## 这个对照能说明什么、不能说明什么
- 能检验：去掉专家示教里早期接近过程（只保留与纠正数据相同长度的抓取前路程）后，C 的优势是否消失。
- 不复现：纠正数据同样路程要用 3.7 秒（专家截断后只用 1.6 秒），即纠正数据里的精细修正（H3）；
  也不复现人类纠正与专家示教在状态分布上的差异。
- C_trunc 与 R 仍有差别：新增专家比原 50 条更快、更抖（抓取前 jerk 2344 对 1561，峰值速度 129 对 110）。

## 测试位置与次数
- 位置：复测中的 **P1 (386, 182)** 和 **P2 (394, 212)**，坐标来自 `results/test_positions.json`；摆放方法、3 px 容差和参考图与复测相同。
- 每个模型每个位置 8 次，共 **32 次**（C_trunc 16 + C 16）；**不中途追加**。
- 顺序见 `protocol/trunc_trial_order.csv`（trial_id U01–U32）：两个位置的先后随机；每个位置内 16 次按 4 次一组，
  每组随机为 ABBA 或 BAAB。随机种子见 `protocol/trunc_order_seed.txt`，脚本 `scripts/make_trunc_order.py`。
- 测试在复测结束的同一天进行；C_trunc 与 C 在本次测试中交替，但与复测中的 R、C 不是交替测试。

## 成功标准、失败分类、记录项目、推理设置
与复测相同（`right_side_retest.md`，并按 `addendum_01.md`、`addendum_02.md` 的补充）：
- 成功：30 秒内方块落入箱子并已被松开，以方块留在箱子里为准，不看夹爪最终状态。
- 失败类型：1 碰到边缘没抓住 / 2 手臂伸不到 / 3 抓起后掉落 / 4 把方块推开；耗尽 30 秒的失败按导致耗时的原因分类，备注写"超时"。
- 记录项目：录像、关节状态、每一步预测的完整 action chunk、实测方块坐标、夹爪合上次数（按附录 01 的规则）。
- 推理设置：temporal ensembling，`n_action_steps=1`，`temporal_ensemble_coeff=0.01`，两个模型相同。
- 中断：只有与模型无关的原因（硬件故障、崩溃、方块被意外碰动）才重做同一个 trial_id，被中断那次保留并注明。
  **补充**：一次运行完整结束（包括跑满 30 秒）后必须当场如实记录结果，不得因为不满意而重做。

## 执行
- 摆放：`python scripts/place_cube_overlay.py --order protocol/trunc_trial_order.csv --log results/trunc_placement_log.csv`
- 运行：`python scripts/run_trial.py U01 --protocol trunc`（盲测，终端和日志里不出现模型信息；结果记入 `results/trunc_outcomes.csv`）。

## 分析计划
- **主要分析**：C_trunc 对同一时段的 C（本次测试），P1 + P2 合并（16 对 16），双侧 Fisher 精确检验，显著性水平 0.05。
- **次要分析（探索性）**：
  1. 本次 C_trunc 与复测中 13:45–15:11 的 R（7/16）、C（15/16）并列比较。**注明：不是交替测试**，复测中的 R、C 与本次的 C_trunc 在不同时段。
  2. **漂移检查**：本次 C 对复测中的 C（P1+P2 为 15/16），Fisher 精确检验；若本次 C 与之明显不同，说明当天条件有漂移，上面的并列比较需谨慎解读。
  3. 各位置的成功率、失败类型、夹爪合上次数、抓取前速度曲线、瞄准误差、向右修正量
     （方法同 `analyze_retest.py` / `analyze_correction.py`），与复测中 R、C 的结果并列（标明是不同时段的结果）。
- **预测（H1）**：C_trunc 的成功率低于 C，接近复测中 R 的水平（P1+P2 为 7/16）。

## 解读方式
- C_trunc ≈ R：支持 H1（缺少早期接近过程是主要原因）。
- C_trunc ≈ C：H1 不足以解释差距，剩下 H3（以及未控制的差别）。
- 介于两者之间：H1 与 H3 都有贡献。
- 操作化（建议，供确认）：把 C_trunc 的成功次数 k（共 16 次）分别与 R（7/16）和 C（15/16）做双侧 Fisher 精确检验；
  与 C 显著不同（p < 0.05）且与 R 无显著差别 → 支持 H1；与 R 显著不同且与 C 无显著差别 → H1 不足以解释；
  其余情形（与两者都显著不同，或都无显著差别）→ 按"介于之间或证据不足"报告，不硬判。
  16 次的样本量只能分辨明显的差别，介于两者之间的情形很难确定。

## 局限
- 每格 8 次，样本小；C_trunc 只训练了一个种子。
- 复测中的 R、C 与本次 C_trunc 不是交替测试，存在同一天内的时间漂移风险（用本次 C 作为漂移检查）。
- C_trunc 与 R 在数据内容上除缺失的接近过程外还有其他差异（新增专家更快、更抖；没有人类纠正的修正动作）。
- 成败由人工判断，盲测依赖操作者不去查看对应关系。
